# Glossary

The vocabulary these decisions use. Terms are added when a decision depends on them, and a term
that changes meaning gets a new line rather than a quiet redefinition.

## The package

| Term                 | Meaning                                                                                                                                                                                        |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Component family** | A source directory, an import subpath family and a Storybook kind that share conventions. Two exist: `components/ui` (`Components/*`) and `components/ai` (`AI/*`).                            |
| **Storybook kind**   | The first segment of a story's `title`, which is the group it appears under in the sidebar. Deliberately one to one with a component family — see [ADR 0001](adr/0001-ai-component-family.md). |
| **Root barrel**      | `src/index.ts`, generated by `scripts/generate-barrel.mjs` from `components/ui` only. Importing it must never resolve an optional peer.                                                        |
| **Deep import**      | `@konopskidev/ui/components/<family>/<name>`, which resolves to exactly one module. The only way in for anything outside the root barrel.                                                      |
| **Optional peer**    | A dependency the package does not install. The README names it, the component that needs it is deep-import only, and the root barrel must not reach it.                                        |
| **Chromatic opt-in** | `parameters.chromatic.disableSnapshot: false` on exactly one story per component. Snapshots are off project-wide, so this is how a component joins the visual suite.                           |

## The AI SDK

| Term                        | Meaning                                                                                                                                                                                                               |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **UIMessage**               | The SDK's client-side message: `id`, `role`, `parts`, optional `metadata`. It is the source of truth a chat UI renders, as opposed to the `ModelMessage` sent to the model.                                           |
| **UIMessagePart**           | One entry of `message.parts`: `text`, `reasoning`, `tool-<name>`, `dynamic-tool`, `source-url`, `source-document`, `file`, `data-<name>`, `step-start`, `custom` (plus the experimental `steering-message`).          |
| **Part state**              | The status a part carries. `text` and `reasoning` use `streaming \| done`; a tool part uses `input-streaming`, `input-available`, `approval-requested`, `approval-responded`, `output-available`, `output-error`.     |
| **Tool invocation**         | A tool part: `type: tool-<name>`, `toolCallId`, `input`, and then either `output` (with `output-available`) or `errorText` (with `output-error`). `dynamic-tool` is the same shape for tools the client did not type. |
| **Approval request**        | A tool part in `approval-requested`: it carries `approval.id`, `requestReason`, optional `descriptor`, and `isAutomatic`. The answer goes back through `addToolApprovalResponse({ id, approved, reason })`.           |
| **Part dispatcher**         | The component that maps `message.parts` onto renderers, with an override registry per tool or data-part name. Deferred by [ADR 0007](adr/0007-dispatcher-deferred.md); the name `message-parts` is reserved.          |
| **Citation marker**         | The inline, numbered reference inside a `text` part that points at one entry of `sources`. Default syntax `[n]`, overridable per provider — see [ADR 0013](adr/0013-inline-citations.md).                             |
| **Data part**               | A `data-<name>` part whose payload the app defines. Rendered by `data-part` as a labelled JSON fallback, or by the app's `render` prop ([ADR 0012](adr/0012-data-part-fallback.md)).                                  |
| **Presentational contract** | Components take data and render it. No `useChat`, no transport, no message state: the app owns those, the library owns how a part looks.                                                                              |
| **Part-shaped props**       | A prop that is the SDK part itself (`part={part}`) rather than its fields. Decided in [ADR 0002](adr/0002-type-only-sdk-coupling.md): components take the part, never a flattened `state`/`input`/`output` set.       |
| **Type-only coupling**      | The package imports SDK types with `import type` and nothing else, so `ai` is an optional peer with no runtime presence. The family is unusable without the SDK's types, and that is the accepted trade.              |
