The unit of work

One component, three files

A component is not done when it renders. Each of the 63 lives beside the two files that prove it: one that documents the API from its types, one that pins its behaviour.

1button.tsx

The component

The public API, and nothing that belongs to a consumer.

  • Typed props, CVA variants, asChild
  • A data-slot on every part
  • cn(…, className) always last
2button.stories.tsx

The documentation

Written once, rendered in both themes, correct because docgen reads types.

  • Every prop grouped by category
  • A play function for the hard interactions
  • axe runs against every story
3button.test.tsx

The behaviour

What the component promises, asserted through roles and names.

  • Roles, labels, focus, keyboard
  • data-slot beats a class selector
  • No assertion on a Tailwind class
